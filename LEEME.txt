PUBLICACIÓN
1. Haz una copia de seguridad del sitio actual.
2. Sube todos estos archivos y la carpeta assets a la raíz de tu repositorio GitHub Pages.
3. Mantén los nombres de archivo y la carpeta assets tal como están.
4. No cambies tu backend de Render ni la base PostgreSQL para esta actualización de frontend.
5. Abre index.html desde tu dominio GitHub Pages y prueba registro, inicio de sesión, catálogo y creación de pedidos.

IMPORTANTE SOBRE LA CLASIFICACIÓN
El backend actual devuelve /api/catalog. El frontend clasifica los productos usando los campos tipo/category/categoria/type y, como respaldo, palabras del nombre e ID.
Edita PRODUCT_RULES en assets/config.js para ajustar productos concretos:
- completeAccounts: cuentas completas
- profiles: perfiles
- subscriptions: suscripciones
- applications: aplicaciones
- games: videojuegos

RECOMENDACIÓN
Para una clasificación infalible a largo plazo, cada producto debería tener en el backend un campo category o tipo con uno de estos valores:
completeAccounts, profiles, subscriptions, applications, games.
Las reglas por palabras son un respaldo, no sustituyen una categoría explícita en la base de datos.

AUTENTICACIÓN Y PEDIDOS
Se conservan las rutas que ya usaba el frontend:
GET /api/catalog
POST /api/auth/register
POST /api/auth/login
GET /api/me
POST /api/orders
POST /api/orders/{id}/cancel
GET /api/admin/orders
POST /api/admin/orders/{id}/paid

La sesión se guarda en localStorage con la clave krma_token, para que siga activa al cambiar entre páginas del mismo dominio.

SEGURIDAD
- No publiques ADMIN_SECRET en archivos HTML o JavaScript.
- El panel administrativo solicita la clave al administrador y la envía en el encabezado X-Admin-Secret, igual que tu sistema actual.
- La confirmación de pago es manual: verifica el ingreso real en Wompi antes de marcar un pedido como pagado.
- Usa HTTPS y conserva la política de privacidad y tratamiento de datos personales.
